7/// Monta o DTO de uma requisição a partir de qualquer um dos dois formatos.
8///
9/// **Não tem `self`.** Uma factory não carrega estado: ela é um namespace
10/// tipado, um ZST que existe só para dar nome ao par de leituras de uma
11/// mensagem. É o que permite pedi-la por parâmetro de tipo — `Body<LoginRequestFactory>`
12/// — em vez de instanciá-la.
13///
14/// ## Por que dois métodos e não um `Deserialize`
15///
16/// O caminho JSON recebe um `Map` já parseado e **escolhe** os campos, em vez de
17/// deixar o serde derivar a struct inteira. A diferença aparece num campo
18/// obrigatório ausente: com `Deserialize`, o serde falha antes de o handler
19/// existir e a resposta é um 400 genérico; escolhendo campo a campo, o DTO
20/// recebe `None`, o `TableModule` recusa e o cliente ganha um 422 dizendo
21/// **qual** campo faltou — e todos os que faltaram, de uma vez.
22pub(crate) trait RequestFactory {
23    /// O DTO que esta factory produz.
24    ///
25    /// `Send` porque atravessa o `.await` do caso de uso.
26    type Message: Send;
27
28    /// Lê a mensagem de um objeto JSON já parseado.
29    fn from_json(source: &Map<String, Value>) -> Result<Self::Message, ApiError>;
30
31    /// Lê a mensagem de um buffer `FlatBuffers`.
32    fn from_flatbuffer(bytes: &[u8]) -> Result<Self::Message, ApiError>;
33}

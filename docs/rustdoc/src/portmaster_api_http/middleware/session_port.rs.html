7/// A sessão da requisição corrente.
8///
9/// Leitura e nada mais. Quem **põe** um usuário na sessão é o layer que confere
10/// o token, e ele alcança o escritor por dentro do módulo — de fora não há como
11/// um controller declarar-se autenticado, que é a única forma de o `401` valer
12/// alguma coisa.
13///
14/// ## O gate está nos getters, não nos middlewares
15///
16/// [`Self::current_user`] falha se o middleware de token não rodou antes. Parece
17/// redundante — se o middleware está no router, ele rodou — mas é o que
18/// transforma um erro de ordenação da pilha em falha imediata e nomeada, em vez
19/// de um `None` silencioso que o controller leria como "não há sessão" e
20/// responderia `401` para todo mundo.
21///
22/// A diferença aparece no dia em que alguém reordena os `.layer()`: com o gate,
23/// a primeira requisição explica o problema; sem ele, a API simplesmente para de
24/// autenticar e ninguém sabe por quê.
25pub(crate) trait SessionPort: Clone + Send + Sync + 'static {
26    /// O usuário da sessão, ou `None` em rota pública.
27    ///
28    /// Falha — e não devolve `None` — quando o middleware de token não rodou.
29    fn current_user(&self) -> Result<Option<UserContext>, ApiError>;
30
31    /// O usuário da sessão, ou `401`.
32    ///
33    /// O atalho que todo handler protegido usa. O **`401` é o único status que
34    /// nasce nesta camada**: falta de sessão é a única coisa que o `app` não tem
35    /// como saber.
36    fn require_user(&self) -> Result<UserContext, ApiError>;
37}

1//! O contexto da requisição: as portas na raiz, as implementações em `intern`.
2//!
3//! ## Quem usa o quê
4//!
5//! **Abrir** um escopo é assunto de middleware, e **consumir** o que há dentro
6//! dele é assunto de controller. A divisão do diretório é essa e nada mais: os
7//! `*_port.rs` daqui são o que um controller injeta, e [`intern`] guarda os
8//! layers que abrem os escopos e os contextos que os atendem.
9//!
10//! É o que fecha a porta para o abuso óbvio. O escritor de cada contexto é
11//! `pub(super)`, alcançado só pelo layer irmão — de fora de `intern` não há
12//! como acrescentar um usuário à sessão sem passar pelo middleware de token,
13//! nem carimbar um `request_id` diferente do que a requisição recebeu.
14//!
15//! ## Cada middleware é um arquivo
16//!
17//! O `tower::Service` que faz o trabalho e o `tower::Layer` que o aplica moram
18//! juntos. Eram dois arquivos, e o `Service` nunca foi nomeado de fora: quem
19//! monta a pilha aplica o `Layer`. A pilha continua composta por generics — cada
20//! `.layer()` embrulha o serviço num tipo novo —, então não há `dyn` nem
21//! `middleware::from_fn` solto em ponto nenhum dela.
22

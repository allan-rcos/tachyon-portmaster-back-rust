1//! Os segredos e knobs de runtime desta apresentação.
2//!
3//! Esta camada é a **única** que lê ambiente. Ela monta as structs de segredo de
4//! todas as camadas — [`portmaster_app::AppSecrets`] chega pronta ao `register`,
5//! que a distribui para dentro. As camadas internas nunca leem uma variável:
6//! recebem o que precisam por argumento, e por isso são testáveis sem preparar
7//! ambiente nenhum.
8//!
9//! ## Uma chain, um grupo por elo
10//!
11//! A leitura não é uma função só. Cada grupo de configuração é um elo em
12//! `chain`, que se declara sozinho na slice que o linker preenche e escreve no
13//! slot dele do `BootDraft`. O [`secrets::Secrets::load()`] percorre a slice,
14//! congela o rascunho e descarta tudo — a chain não sobrevive ao boot.
15//!
16//! É a Chain of Responsibility do `DotEnvChain` do PHP, pela mesma razão que ela
17//! existe lá: a alternativa era uma classe com um campo, um setter e um ramo de
18//! validação por variável, que só cresce.
19//!
20//! ## O que é runtime e o que é build
21//!
22//! Aqui só entra **segredo ou identidade de deploy**: senha do banco, segredo do
23//! JWT, host/porta, quem é este servidor na composição do Snowflake. Knobs de
24//! **arquitetura** — tamanho de pool, capacidade e TTL dos caches, estratégia de
25//! id — são features de compilação, e não têm variável correspondente de
26//! propósito: um `if` em produção sobre uma decisão de arquitetura é um bug
27//! esperando o dia de errar.

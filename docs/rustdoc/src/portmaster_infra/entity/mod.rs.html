1//! As entities: onde o domínio encosta na tabela.
2//!
3//! Cada entity implementa o trait de domínio correspondente **e** concentra tudo
4//! que é de banco — nome de tabela, nome de coluna, tipo de cada campo. Isso
5//! mantém o model do `domain` limpo de qualquer vestígio de persistência, e é o
6//! que permitiria trocar de banco mexendo só aqui.
7//!
8//! Como o trait de domínio é somente-leitura, uma entity **não consegue editar**
9//! um objeto vindo de outra camada: ela o **recria** a partir do trait, por um
10//! `from_domain`. A ausência de setters não é inconveniente, é a garantia.
11//!
12//! ## A entity **é** a linha
13//!
14//! Não há `*_row.rs`, e também não há `from_row` escrito à mão: cada entity
15//! deriva `sqlx::FromRow`, e o que antes se escrevia no corpo daquela função
16//! virou atributo do campo que o exige — `try_from` para o id e para o índice de
17//! enum, `json` para a coluna `JSON`, `default` para o campo que não é coluna.
18//!
19//! O ganho não é o tamanho: é que uma coluna nova passa a ser um campo, e não um
20//! campo mais uma linha de leitura que pode ficar para trás.
21//!
22//! A identidade é um [`EntityId`](entity_id::EntityId) e não dois campos. Antes
23//! cada entity guardava `id: String` e `raw_id: i64` lado a lado, mantidos em
24//! sincronia à mão nos dois construtores.

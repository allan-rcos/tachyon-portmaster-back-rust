7/// Inicializa a `infra`.
8///
9/// Não devolve mais um provider: o provider é estático, então não há objeto a
10/// entregar. O que sobrou é dar os segredos a quem precisa deles e confirmar
11/// que o banco do outro lado existe.
12///
13/// Quem precisa dos segredos é um só: o pool. Ele nasce **preguiçoso** — abrir
14/// não toca a rede —, e é o `ping` logo abaixo que faz a primeira conexão de
15/// verdade. Falhar ali derruba o boot de propósito: subir com um banco
16/// inalcançável só adia a descoberta para a primeira requisição, com o processo
17/// já reportado como saudável.
18///
19/// Os quatro mapas em memória não aparecem aqui. Eles não têm o que configurar
20/// — os tetos são `const` de build — e nascem sozinhos na primeira vez que
21/// alguém pede um repositório que os use.
22///
23/// Chamar isto duas vezes não é erro, e a segunda não muda nada: o pool já está
24/// fixado, e os segredos que chegarem depois são ignorados.
25pub async fn register(secrets: InfraSecrets) -> anyhow::Result<()> {
26    MariaDbRepositoryProvider::install(&secrets)?;
27
28    ScopeProvider::ping().await

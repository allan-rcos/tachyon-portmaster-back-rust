1//! # portmaster-infra
2//!
3//! Adaptadores de I/O. Depende só do `domain`, e só para pegar os traits de
4//! objeto de domínio e implementá-los nos seus entities.
5//!
6//! É dona dos **ports de I/O** — repositórios, `UnitOfWork`, cache, `Logger`.
7//! Eles ficam aqui e não no `domain` porque quem os consome é o `app`, que
8//! conhece esta camada; o `domain` não sabe que existe banco.
9//!
10//! ## O `i64` para de existir aqui
11//!
12//! Esta é a única camada que enxerga o inteiro do Snowflake. Ao ler uma linha
13//! deriva o base62 que o trait expõe; ao gravar, decodifica de volta para
14//! `BIGINT`. Se o id físico mudar um dia, só este mapeamento muda.
15//!
16//! ## O que não mora aqui
17//!
18//! **JWT.** É assunto exclusivo do `api-http`: nem esta camada nem o `app` sabem
19//! o que é um token. O que existe aqui é a primitiva de marcador — um booleano
20//! com prazo — e é a apresentação que decide chamar aquilo de sessão.

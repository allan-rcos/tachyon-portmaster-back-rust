Os objetos de domínio: um contrato de leitura por arquivo.

Todo trait aqui é somente-leitura — só getters. Quem recebe um User consegue lê-lo e não alterá-lo, e é isso que impede o app ou o api de mudarem um e-mail sem passar pela validação do TableModule.

Nenhum leva sufixo, e a ausência é a informação: User é o domínio, e UserModel — a implementação — é outra coisa, que mora dentro do TableModule que a constrói e não sai de lá.
